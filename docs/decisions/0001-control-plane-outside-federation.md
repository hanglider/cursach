# ADR 0001. Управляющий контур живёт вне федерации, в control-кластере kind

Дата: 2026-09-13. Закрывает open-questions 3.1.

## Статус

Принят.

## Контекст

Контур управления (Registry, Meta-Scheduler, DR Controller, Thanos Querier,
шлюз, Grafana) должен наблюдать за кластерами федерации и переживать отказ
любого из них. Если контур разместить внутри одного из управляемых кластеров,
отказ именно этого кластера уносит наблюдателя, и сценарий 1 (отказ кластера)
становится непроверяемым.

Варианты размещения: отдельный kind-кластер `control`, процессы прямо на
хост-машине, docker-compose рядом с kind.

## Решение

Все компоненты контура разворачиваются в отдельном kind-кластере `control`,
который не входит в федерацию и не получает workload'ов. В федерации остаются
только агенты сбора и исполнения: Prometheus с Thanos sidecar, OTel Collector,
Kyverno, Chaos Mesh, сам тестовый сервис.

Единственное исключение — генератор нагрузки k6: он работает на хост-машине
(ADR 0008). Хост тоже вне федерации, инвариант соблюдён.

Инвариант 1 architecture §9: ни один компонент контура не размещается в
кластере федерации.

## Последствия

Плюсы:

- Отказ любого кластера федерации не затрагивает наблюдателя и решателей.
- Компоненты контура разворачиваются теми же средствами (helm, kubectl), что
  и всё остальное; воспроизводимость из репозитория.

Минусы:

- Третий kind-кластер на машине с 16 GB RAM и 8 GB docker-VM. Именно из-за
  него федерация ограничена двумя кластерами (ADR 0013).
- Control-кластер сам не резервируется: его отказ роняет весь контур. Для
  стенда это приемлемо, для production — нет; работа и не претендует на
  production-ready (vision, «Границы работы»).
- Компонентам контура нужен сетевой доступ к API-серверам и сервисам всех
  кластеров федерации — решается общей docker-сетью (ADR 0021).
