# ADR 0005. Нормализация scoring-функции по latency budget; правило для отсутствующих метрик

Дата: 2026-09-13. Закрывает spec 8.3 (часть про формулу), open-questions 2.1 п. 1.

## Статус

Принят.

## Контекст

Формула spec §4.5 `w1*(1 - error_rate) + w2*(1/latency_p95) + w3*(1 - saturation)`
не нормирована: второе слагаемое при p95 = 10 мс даёт 100, при 1 мс — 1000, и
подавляет остальные независимо от весов. Планировщик вырождается в выбор по
одной латентности. Кроме того, не было определено, как считать score, когда
метрик кластера нет (`slo_status = unknown`, ADR 0018 оставляет такие кластеры
в кандидатах) или они устарели.

## Решение

```
latency_score = 1 - min(latency_p95 / latency_budget, 1)
score = w1*(1 - error_rate) + w2*latency_score + w3*(1 - saturation)
```

- `latency_budget = 200 мс` — целевой p95 из spec §1.3; флаг
  `--latency-budget`, по умолчанию 200ms. Scoring привязан к SLO, а не к ещё
  одной независимой константе.
- Все три слагаемых в [0, 1]; при `w1 + w2 + w3 = 1` score тоже в [0, 1].
- **Отсутствующая или устаревшая метрика** (нет строки в `cluster_metrics`,
  или `observed_at` старше двух периодов опроса каталога, 60 с) даёт своему
  слагаемому нейтральное значение 0.5. Кластер со `slo_status = unknown`
  получает score 0.5 по всем трём. Пессимистичный 0 отклонён: он превращал бы
  отсутствие метрик в основание избегать кластер, что по духу нарушает
  инвариант 6.
- **Ничья** (разница score меньше 1e-6) разрешается round-robin по тем же
  правилам, что у наивного планировщика (ADR 0020). Следствие: без сигнала
  meta-scheduler вырождается ровно в наивный, и разница между ними — строго
  разница в сигнале.
- Формула в spec §4.5 заменена на нормализованную.

## Последствия

Плюсы:

- Веса интерпретируемы: `w1 = 0.5` означает «половина решения — error rate».
- Latency budget связывает планировщик с целевым показателем.

Минусы:

- Слагаемое латентности насыщается на 200 мс: кластеры с p95 = 300 и
  3000 мс равны по этому признаку. Различает их только error rate, который
  при большой латентности растёт через таймауты frontend'а (ADR 0014).
- При 50 RPS saturation на стенде почти не меняется (ADR 0008); третье
  слагаемое будет давать почти константу. Это ограничение стенда, а не
  формулы.
- Нейтральное 0.5 для `unknown` означает, что кластер без метрик проиграет
  здоровому, но выиграет у деградировавшего. Это осознанный компромисс; в
  отчёте оговаривается.
