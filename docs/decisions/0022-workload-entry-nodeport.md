# ADR 0022. Вход в кластер федерации: NodePort на каждый workload, адрес узла по IP

Дата: 2026-09-13. Закрывает вопрос, оставленный ADR 0017 и 0021 на задачу 1.

## Статус

Принят.

## Контекст

Шлюз control-кластера (ADR 0017) должен доставить запрос `w-<n>.fed.local`
до Service `w-<n>` внутри кластера федерации. Варианты: второй L7-шлюз в
каждом кластере федерации (ещё около 200 МБ на кластер и динамическая
конфигурация внутри федерации), hostPort на поде, NodePort на Service.
Отдельно: как адресовать узел кластера из control — по имени контейнера
docker или по IP.

## Решение

- **NodePort на каждый workload.** Service `w-<n>` типа NodePort с портом
  `30000 + n mod 2000`; порт выводится из номера, состояние не хранится.
  `Backend` Envoy Gateway указывает на `<IP узла>:<порт>`. Внутри федерации
  никаких дополнительных компонентов и никакой динамической конфигурации.
- **Адрес узла — IP из `docker inspect`.** Проверено 2026-09-13: имена
  контейнеров kind (`cluster-a-control-plane`) резолвятся из подов
  control-кластера, но это делает резолвер OrbStack, а не docker; на другом
  рантайме поведение иное. IP работает везде.
- IP берётся при каждом размещении, а не кэшируется при старте стенда;
  после перезапуска контейнеров kind ничего перерегистрировать не нужно.

## Последствия

Плюсы:

- Ноль компонентов в федерации сверх самого сервиса; память экономится там,
  где её меньше всего.
- Планировщику (задача 6) достаточно знать номер workload'а, чтобы создать
  все четыре объекта: Deployment, Service, Backend, HTTPRoute.

Минусы:

- Два прыжка на пути клиента: Envoy → kube-proxy NodePort → под. Клиентская
  латентность включает оба; серверная (SLI каталога) — нет. На стенде
  прыжок стоит доли миллисекунды (p95 клиентский около 3 мс без нагрузки
  на сервис).
- Диапазон NodePort ограничен (kind: 30000–32767); при `TTL = 180 с` и
  `N = 30 с` одновременно живёт около шести портов, коллизий нет, но
  workload'ы с номерами, отличающимися на 2000, делят порт. Для длительности
  прогонов (13 мин) недостижимо.
- Порт 30080 занят прокси Envoy в control; в кластерах федерации он свободен,
  но схема нумерации его не обходит. Не проблема, пока workload'ы не
  размещаются в control, чего инвариант 1 и не допускает.
- Трафик из control в федерацию идёт по docker-сети без TLS. Для стенда
  приемлемо.
