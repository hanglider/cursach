# ADR 0013. Федерация из двух кластеров плюс control

Дата: 2026-09-05 (решение), 2026-09-13 (оформление). Закрывает
open-questions §0.

## Статус

Принят.

## Контекст

spec допускает 2–3 кластера федерации. Машина разработчика: 16 GB RAM,
docker-VM OrbStack с лимитом 8 GB. Каждый кластер федерации несёт
Prometheus, Thanos sidecar, OTel Collector, Kyverno, Chaos Mesh и тестовый
сервис; control-кластер — весь контур (ADR 0001).

## Решение

Стенд: `control` + `cluster-a` + `cluster-b`. Третий кластер федерации
(`cluster-c`) добавляется только после того, как контур заработает
end-to-end, и только если ресурсы позволят. Все три сценария spec §6 работают
на двух кластерах.

## Последствия

Плюсы:

- Стенд помещается в docker-VM без поднятия лимита; меньше времени на
  `make stand-up`.

Минусы:

- В сценарии 2 после деградации одного кластера у планировщика остаётся
  единственный кандидат: выбор бинарный. Сравнение с наивным остаётся
  корректным (round-robin продолжает отправлять половину размещений в
  деградировавший кластер), но эффект scoring при трёх кластерах был бы
  нагляднее.
- Механизмы, которые проявляют себя только при N ≥ 3 (например, ранжирование
  нескольких здоровых кандидатов по латентности), на стенде не проверяются.
- При добавлении `cluster-c` придётся повторить прогоны, чтобы результаты
  были сопоставимы.
