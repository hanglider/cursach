# ADR 0020. Наивный планировщик: round-robin по `/clusters/eligible`, один бинарь с флагом

Дата: 2026-09-13. Закрывает open-questions 3.8.

## Статус

Принят.

## Контекст

Целевой показатель «снижение error rate ≥ 20% vs наивный выбор» требует
наивного планировщика на тех же сценариях. Он обязан соблюдать те же hard
constraints, иначе разница в error rate — смесь двух эффектов (инвариант 3).
spec §4.5 допускает round-robin или random.

## Решение

- Наивный планировщик — **round-robin** по списку `eligible` из ответа
  каталога (ADR 0018), отсортированному по `id`. Счётчик в памяти процесса;
  сброс при перезапуске допустим и фиксируется в логе.
- Метрики и `slo_status` (кроме `down`, который отсекает сам каталог)
  наивный планировщик **не читает**. В `placement_decisions.candidates` он
  пишет всех кандидатов с `score: null` и снимком метрик из ответа каталога,
  чтобы офлайн-анализ мог посчитать, что выбрал бы умный.
- Оба планировщика — один бинарь `scheduler/`, режим задаётся флагом
  `--scheduler=meta|naive`; значение попадает в `scheduler_kind` каждого
  решения. Всё остальное (watch, создание ресурсов, маршрут на шлюзе, запись
  решения) общее.
- Наивный планировщик не улучшается (CLAUDE.md «Не подменять baseline»).

Round-robin, а не random: детерминированность облегчает воспроизведение
прогона и объяснение результата; при двух кластерах математическое ожидание
совпадает.

## Последствия

Плюсы:

- Разница между планировщиками сводится строго к одному блоку кода —
  выбору из `eligible`. Всё остальное идентично, что и требуется для честного
  сравнения.
- Переключение без пересборки; эксперименты одним образом.

Минусы:

- При двух кластерах round-robin строго чередует: при чётном числе
  размещений под отказом ровно половина уходит в деградировавший кластер,
  при нечётном — с перекосом на одно. С `N = 30 с` за 5 минут это 10
  размещений, эффект мал; фиксируется.
- Общий бинарь означает, что ошибка в общей части (например, в создании
  маршрута) одинаково искажает оба ряда; это скорее плюс для сравнения, но
  минус для поиска причины.
