# ADR 0002. Thanos без object storage: экспорт результатов прогонов вместо MinIO

Дата: 2026-09-13. Закрывает spec 8.7, open-questions 1.6.

## Статус

Принят.

## Контекст

Thanos sidecar умеет загружать блоки TSDB в object storage, что даёт
долгосрочное хранение и глобальные запросы поверх истории. На стенде это
означало бы отдельный компонент (MinIO, около 300 МБ памяти) в control-кластере
при лимите docker-VM 8 GB. architecture §2.2 предлагал MinIO.

Задача хранения на стенде одна: результаты прогонов должны переживать
переустановку стенда и быть доступны для постфактум-анализа.

## Решение

Object storage не разворачиваем. Thanos sidecar работает только как StoreAPI
поверх живого Prometheus каждого кластера; Thanos Querier в control-кластере
агрегирует sidecar'ы федерации и sidecar control-Prometheus (в него k6 пишет
клиентские метрики, ADR 0008). Retention Prometheus — 15 дней по умолчанию.

Сырые ряды каждого прогона выгружаются скриптом из Thanos Query API
(`query_range` за окно прогона, шаг не крупнее периода scrape) в
`experiments/results/<run-id>/` и коммитятся. Список выгружаемых рядов —
часть скрипта и версионируется вместе с ним. Именно экспорт, а не object
storage, является долгосрочным хранилищем результатов.

MinIO добавляется позже, если появится задача, которую экспорт не покрывает.

## Последствия

Плюсы:

- Минус один компонент и около 300 МБ памяти в control-кластере.
- Результаты лежат в git в явном виде; анализ (`analysis/`) не зависит от
  живого стенда.

Минусы:

- История сверх 15 дней теряется, если не была выгружена. Забытый экспорт
  после прогона — потерянный прогон; экспорт нужно встроить в скрипт-раннер
  эксперимента, а не делать отдельным шагом.
- Переанализировать старый прогон новым PromQL-запросом можно только по тем
  рядам, что были выгружены. Поэтому выгружаются сырые счётчики и гистограммы
  (`http_requests_total`, `http_request_duration_seconds_bucket`, k6-ряды),
  а не только производные SLI.
- Thanos Store Gateway и Compactor не используются; Thanos сводится к
  sidecar + Querier.
